## 第一轮：MySQL

### Q1 ⭐ 为什么用 B+ 树做索引？

**答：**

> ① 非叶子节点只存索引不存数据 → 单页能放更多键 → 树更矮 → 磁盘 IO 更少；
> ② 叶子节点形成有序链表 → 范围查询和排序高效；
> ③ 相比 B 树，范围扫描不用回到上层节点；相比哈希索引，支持范围查询和最左前缀。

🔁 追问：聚簇索引和二级索引？→ 聚簇索引叶子存整行数据（主键即数据）；二级索引叶子存主键值，查询非索引字段需回表。

---

### Q2 ⭐ 什么情况索引会失效？

**答：** 索引列参与函数/运算（`WHERE DATE(created_at)=...`）、隐式类型转换（字符串列传数字）、`LIKE '%xx'` 前导模糊、`OR` 一侧无索引、联合索引不满足最左前缀、优化器评估全表更快（区分度低）。排查用 `EXPLAIN` 看 type/key/rows/Extra。

🔁 追问：EXPLAIN 重点看什么？→ type（ALL 最差，ref/range 可接受）、key 是否命中、rows 扫描行数、Extra（Using filesort/Using temporary 需优化，Using index 是覆盖索引）。

### Q3 ⭐ 事务隔离级别和问题？

| 级别 | 脏读 | 不可重复读 | 幻读 |
| --- | --- | --- | --- |
| 读未提交 | ✅ | ✅ | ✅ |
| 读已提交 | ❌ | ✅ | ✅ |
| 可重复读（默认） | ❌ | ❌ | ❌（间隙锁） |
| 串行化 | ❌ | ❌ | ❌ |

MVCC 用 undo 版本链 + ReadView 实现一致性读；RR 下用间隙锁防幻读。

🔁 追问：测试怎么验证隔离性？→ 两个会话并发：一边读一边改/插，验证结果符合目标隔离级别；并发下单验证锁与超卖。

### Q4 死锁怎么产生的？怎么排查？

**答：** 两个事务以相反顺序持有并等待锁；InnoDB 自动检测并回滚代价小的事务。排查：`SHOW ENGINE INNODB STATUS` 看 LATEST DETECTED DEADLOCK、应用日志。预防：统一加锁顺序、缩小事务、用乐观锁/唯一索引、重试机制。

### Q5 慢查询怎么优化？

**答：** 慢查询日志 → `pt-query-digest` 聚合 → EXPLAIN 分析 → 加索引/改写 SQL（避免 SELECT *、深分页用游标或延迟关联）→ 拆分大事务 → 读写分离/缓存 → 归档冷数据/分库分表。

```sql
-- 深分页优化：延迟关联
SELECT t.* FROM orders t
JOIN (SELECT id FROM orders WHERE status='PAID' ORDER BY id LIMIT 100000, 20) x
ON t.id = x.id;
```

### Q6 ⭐ 给定场景写 SQL：订单表求每个用户最近一笔订单

```sql
SELECT *
FROM (
  SELECT o.*,
         ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY created_at DESC) AS rn
  FROM orders o
) t
WHERE rn = 1;
```

🔁 追问：三个窗口函数区别？→ ROW_NUMBER 不重复（1,2,3）、RANK 并列跳号（1,1,3）、DENSE_RANK 并列不跳号（1,1,2）。

### Q7 SQL：连续登录 3 天的用户？

```sql
SELECT user_id
FROM (
  SELECT user_id, login_date,
         DATE_SUB(login_date, INTERVAL ROW_NUMBER()
                  OVER (PARTITION BY user_id ORDER BY login_date) DAY) AS grp
  FROM (SELECT DISTINCT user_id, DATE(login_time) AS login_date FROM login_log) d
) t
GROUP BY user_id, grp
HAVING COUNT(*) >= 3;
```

思路：日期 - 行号 = 分组键，连续日期同组。

### Q8 测试怎么用 SQL？

- 数据准备：按条件查/构造前置数据；
- 结果校验：接口返回与落库数据比对；
- 对账：订单与流水金额/状态一致性；
- 数据清理：按前缀批量删除测试数据；
- 线上巡检：核心业务数据异常检测（如重复订单号）。

```sql
-- 对账：金额不一致
SELECT o.order_id, o.amount, p.amount
FROM orders o JOIN payments p ON o.order_id = p.order_id
WHERE o.amount <> p.amount;
```

## 第二轮：Redis 与 MQ

### Q9 ⭐ 缓存穿透、击穿、雪崩的区别和方案？

| 问题 | 原因 | 方案 |
| --- | --- | --- |
| 穿透 | 查不存在的数据打到 DB | 空值缓存、布隆过滤器、参数校验 |
| 击穿 | 热点 key 过期瞬间 | 互斥锁重建、逻辑过期、永不过期+异步刷新 |
| 雪崩 | 大量 key 同时失效 | 过期时间加随机、多级缓存、熔断降级 |

**测试验证点：** 构造不存在的 key 高频请求看 DB 压力；热点 key 过期瞬间并发；批量过期后系统表现与降级。

### Q10 缓存和数据库一致性怎么保证？怎么测？

**答：** 常用 Cache Aside：先更新 DB 再删除缓存；延迟双删；最终一致用 binlog 订阅刷新。测试：并发读写交错，核对缓存与 DB 数据；模拟删除失败、网络分区；验证最终收敛时间。

### Q11 分布式锁怎么实现？测试点？

**答：** Redis `SET key value NX EX` + 唯一 value + Lua 释放 + 续期（看门狗）；ZK 临时顺序节点。测试点：锁过期业务未完成、误删他人锁、重入、等待超时、Redis 故障降级、并发抢锁唯一性。

### Q12 ⭐ MQ 消息丢失/重复/顺序怎么测？

| 问题 | 机制 | 测试方法 |
| --- | --- | --- |
| 丢失 | 确认机制、持久化、手动 ACK | 杀消费者/断 Broker，验证消息不丢、重投 |
| 重复 | 重试、重平衡 | 重复投递同一消息，验证消费幂等 |
| 顺序 | 同 key 同分区 | 并发发送同 key 消息，验证消费顺序与业务状态 |

🔁 追问：消息积压怎么排查？→ 消费速率 vs 生产速率、消费者异常/慢逻辑、热点分区、Broker 资源；处理：扩容消费者、限流生产、临时专题消费。

### Q13 消息幂等怎么实现？

**答：** 唯一业务键 + 去重表/Redis SETNX + 状态机校验（已处理直接返回）。测试：重复投递、并发消费同一消息、消费后崩溃重投。

## 第三轮：网络

### Q14 ⭐ TCP 三次握手/四次挥手，为什么？

**答：**

> 三次握手：SYN → SYN+ACK → ACK。目的是双方确认彼此的收发能力，并防止历史连接请求造成错误连接。
> 四次挥手：FIN → ACK → FIN → ACK。TCP 全双工，两个方向需要分别关闭，所以比握手多一次。
> 第三次握手失败：客户端认为已建立，服务端停在 SYN_RCVD 并重传，超时释放；客户端发数据时服务端回 RST。

🔁 追问：TIME_WAIT 是什么？→ 主动关闭方等待 2MSL，保证最后 ACK 可达、旧连接报文消散；过多可调参数或连接复用。
🔁 追问：CLOSE_WAIT 过多？→ 被动关闭方没有调用 close()，通常是连接泄漏的代码 Bug。

### Q15 ⭐ HTTP 1.1/2/3 区别？队头阻塞是什么？

**答：** 1.1 持久连接但请求串行，应用层队头阻塞；2 多路复用 + 头部压缩解决应用层 HOL，但 TCP 丢包仍阻塞所有流；3 基于 QUIC（UDP），流级独立，彻底解决。测试关注：多路复用下的并发、连接复用、HTTP/3 回退。

### Q16 WebSocket 和 SSE 的区别？

**答：** WS 全双工、独立协议（101 升级）、需自己实现心跳重连；SSE 服务端单向推、就是 HTTP（text/event-stream）、内置重连。需要客户端频繁发消息用 WS，只需服务端推送用 SSE。

### Q17 HTTPS 握手过程？测试关注点？

**答：** Client Hello → Server Hello + 证书 → 客户端验证证书并生成密钥（公钥加密）→ 双方用对称密钥通信。测试：证书过期/域名不匹配/自签名、TLS 版本、强制跳转、混合内容、证书链完整性。

### Q18 301 和 302 的区别？常见状态码？

**答：** 301 永久重定向（会被缓存），302 临时重定向。其他：401 未认证、403 无权限、404 不存在、405 方法不允许、429 限流、500 服务端异常、502 网关错误、503 不可用、504 网关超时。

## 第四轮：Linux 与排障

### Q19 ⭐ 服务变慢，你用哪些命令排查？

```bash
top / htop            # 负载、CPU、内存
vmstat 1 5            # r 队列、swap、上下文切换
iostat -x 1 5         # 磁盘 %util、await
free -h               # 内存与 cache
df -h / du            # 磁盘空间
ss -lntp / ss -s      # 端口、连接状态统计
sar -n DEV 1          # 网卡流量
lsof -p <pid> | wc -l # 句柄数
```

顺序：先看负载是否超核数 → CPU/内存/IO/网络定位 → 再看应用（线程/GC/连接池）。

### Q20 日志怎么快速分析？

```bash
# 关键字前后 20 行
grep -n -A20 -B20 "ERROR" app.log | head -50

# 统计错误类型 Top
grep -oE "Exception: [A-Za-z]+" app.log | sort | uniq -c | sort -rn | head

# 按时间窗口
awk '$1 >= "2026-09-01 10:00" && $1 <= "2026-09-01 10:30"' app.log

# 大文件实时跟踪
tail -f app.log | grep --line-buffered "ERROR"
```

### Q21 磁盘满了怎么处理？

**答：** `df -h` 确认分区 → `du -sh *` 逐层定位 → 常见：日志膨胀、core dump、临时文件、删除进程占用文件（`lsof | grep deleted`，需重启进程释放）→ 清理/轮转/扩容；同时检查 inode（`df -i`）。预防：logrotate + 磁盘告警。

### Q22 测试环境服务起不来，怎么排查？

**答：** 进程与端口（`ps/ss`）→ 日志（启动报错最常见：配置/依赖/端口冲突/权限）→ 资源（内存/磁盘/inode）→ 依赖（DB/Redis/MQ 连通性）→ 配置（环境变量/配置中心）→ 时间不同步（证书/签名问题）。

## 第五轮：场景综合

### Q23 打开网页很慢，怎么排查？

**参考话术：**

> 从前到后：① DNS 解析与网络（ping/curl -w 分阶段耗时）；② 前端资源（CDN、JS 体积、阻塞渲染）；③ 接口耗时（Network/curl，首字节时间 TTFB）；④ 后端链路（Trace 定位慢 Span：DB/缓存/下游）；⑤ 如果只有部分用户慢：地域、运营商、机型、灰度版本；⑥ 定位后给出优化建议并复现验证。

### Q24 线上订单量突然下降 30%，怎么排查？

**答：** 先确认数据真实性（统计口径/延迟）→ 时间点对齐发布与活动 → 分渠道/机型/地域下钻 → 支付成功率、错误率、接口异常 → 风控/限流是否误伤 → DB/缓存/MQ 指标 → 定位后止损（回滚/开关）并复盘。

### Q25 接口返回慢，怎么判断是 DB 还是代码问题？

**答：** Trace 看 SQL 耗时占比；慢查询日志；EXPLAIN；Arthas trace 方法耗时；如果是 N+1 查询（循环内查库）表现是 SQL 数量异常多；代码问题（序列化大对象、正则、加解密）表现为 CPU 高但 SQL 正常。
