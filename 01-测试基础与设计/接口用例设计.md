# 🔌 接口测试用例设计完全指南

> 接口测试是测试开发的基本盘：比 UI 稳定、比 UI 快、能覆盖 UI 触达不到的异常与权限分支。
> 本文覆盖：前期准备 → 六维设计框架 → 单接口/场景用例 → 常见接口模板 → 检查清单 → 实战演练。

---

## 一、为什么接口测试性价比最高

| 维度 | UI 测试 | 接口测试 |
| --- | --- | --- |
| 稳定性 | 受渲染/网络/设备影响 | 稳定 |
| 速度 | 秒级/条 | 毫秒级/条 |
| 覆盖能力 | 用户可见路径 | 异常、越权、幂等、并发、边界 |
| 维护成本 | 前端改版即失效 | 接口契约不变即稳定 |
| CI 友好 | 重、慢 | 轻、快 |

**适合自动化的接口特征：** 高频回归、核心链路、逻辑稳定、字段可断言、数据可构造。

---

## 二、前期准备

1. **明确契约**：接口路径、方法（GET/POST/PUT/DELETE/PATCH）、Content-Type、入参（必填/可选/默认值）、出参结构、错误码表；
2. **理解业务**：这个接口在业务链路中的位置、上下游依赖、幂等要求、事务边界；
3. **依赖分析**：是否依赖登录态、其他服务、缓存、消息队列、定时任务、第三方；
4. **鉴权方式**：Session/Cookie、Token（JWT）、签名（HMAC/RSA）、OAuth2、双向证书；
5. **环境与数据**：环境地址、账号、测试数据如何准备与回收；
6. **非常规约定**：限流阈值、超时时间、重试策略、灰度开关。

---

## 三、六维用例设计框架

```
功能正确性 ── 正常流程、分支、状态流转
参数校验 ──── 必填、类型、边界、特殊字符、组合
鉴权权限 ──── 未登录、Token 过期、越权（水平/垂直）
数据一致性 ── 落库校验、幂等、并发、事务回滚
性能健壮性 ── 并发、超时、重试、大数据量、降级
安全 ─────── 注入、XSS、敏感信息、重放、限流
```

> 面试答题先给这六维，再展开细节，比直接堆用例点更有结构。

## 四、功能类用例

### 4.1 正常流程

- 合法参数返回成功，业务字段正确；
- 返回字段完整、类型正确、与文档一致（含 null 与空数组的语义区分）；
- 状态码符合规范（200/201/204/400/401/403/404/409/429/500）；
- 分页接口：首页、中间页、末页、总数为 0、每页大小变更。

### 4.2 分支与组合

- 业务分支全覆盖：新/老用户、首单/复购、有券/无券、会员/非会员；
- 参数组合：互斥参数、依赖参数、多选参数；
- 优先级验证：多个规则同时命中时，哪个优先生效（如优惠券叠加规则）。

### 4.3 状态与流转

- 合法状态流转：待支付 → 已支付 → 已发货 → 已完成；
- 非法流转：已完成订单再取消、已退款再退款；
- 超时流转：未支付自动取消、超时自动确认收货；
- 并发流转：支付与取消同时发生。

### 4.4 幂等与重复

- 相同幂等键重复提交：只生效一次，返回一致；
- 不同幂等键相同业务参数：各自生效或按唯一约束拒绝；
- 无幂等设计的写接口：验证唯一索引/状态机兜底。

## 五、参数类用例（最容易漏的部分）

| 类别 | 用例 |
| --- | --- |
| 必填 | 逐个删除必填字段；全部缺失；字段为 null/" "/空字符串 |
| 类型 | 数字传字符串、字符串传数字、布尔传 0/1、数组传对象 |
| 边界 | 最小值-1 / 最小值 / 最小值+1；最大值同理；长度 0/1/上限/上限+1 |
| 格式 | 手机号、邮箱、身份证、日期、时间戳、枚举值、金额两位小数 |
| 特殊字符 | 中文、emoji、换行、引号、反斜杠、HTML 标签、SQL 关键字 |
| 编码 | URL 编码、Base64、Unicode、全角/半角、GBK 环境 |
| 超长 | 超长字符串、超大数组（1 万条）、超深嵌套 JSON |
| 数值 | 0、负数、小数、科学计数、超大数（溢出）、精度（0.1+0.2） |
| 组合 | 合法+非法组合、两个参数互相矛盾（开始时间 > 结束时间） |
| 默认值 | 可选参数不传时的默认行为；传空时是否覆盖默认 |
| 多余字段 | 传未知字段：忽略还是报错（mass assignment 风险） |

## 六、鉴权与权限类用例

| 场景 | 用例 |
| --- | --- |
| 未认证 | 不带 Token/Cookie 调用受保护接口 → 401 |
| 无效凭证 | 伪造/篡改 Token、过期 Token、已注销 Token → 401 |
| 权限不足 | 普通用户调管理接口 → 403；无权限访问他人资源 |
| 水平越权 | 篡改 userId/orderId 访问他人数据（IDOR） |
| 垂直越权 | 低权限调高权限接口；仅前端隐藏入口，直接调接口 |
| 签名 | 篡改参数、错误密钥、过期时间戳、重放（同 nonce 重复） |
| 限流 | 短时间高频请求 → 429；验证阈值与恢复时间 |
| 多端/多角色 | 不同角色权限矩阵逐一验证（用表格穷举） |

**权限矩阵示例：**

| 接口 \ 角色 | 游客 | 普通用户 | VIP | 运营 | 管理员 |
| --- | --- | --- | --- | --- | --- |
| 查询商品 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 下单 | ❌ | ✅ | ✅ | ❌ | ❌ |
| 改价 | ❌ | ❌ | ❌ | ✅（限额） | ✅ |
| 删库 | ❌ | ❌ | ❌ | ❌ | ✅（二次确认） |

## 七、数据类用例

- 数据不存在：不存在的 ID、已删除的数据、软删除数据；
- 数据重复：重复创建、唯一键冲突、重复绑定；
- 数据修改：修改后立即查询、修改历史数据、批量修改部分失败；
- 数据删除：删除后查询为空、删除被引用数据（外键约束）、重复删除；
- 数据兼容：老数据结构、老客户端字段、字段废弃过渡期；
- 数据精度：金额、比例、积分（浮点 vs Decimal）；
- 落库校验：接口成功但 DB 未写、接口失败但 DB 已写（事务）；
- 数据权限：跨租户、跨组织数据隔离。

## 八、性能与健壮性用例

| 场景 | 验证点 |
| --- | --- |
| 并发读 | 响应正常、无缓存击穿 |
| 并发写 | 超卖、重复扣款、锁冲突、死锁重试 |
| 慢依赖 | 下游延迟时超时与降级行为 |
| 重试 | 客户端重试是否放大流量、是否幂等 |
| 大数据量 | 深分页、导出 10 万条、超大响应 |
| 长连接 | 超时设置、心跳、断线重连 |
| 限流熔断 | 阈值准确性、拒绝策略、恢复 |
| 资源 | 连接池、线程池耗尽后的表现 |

## 九、安全类用例

| 类别 | 用例 |

## 十、单接口用例 vs 场景用例

| 类型 | 目标 | 示例 |
| --- | --- | --- |
| 单接口 | 验证接口自身契约与逻辑 | 登录接口参数/鉴权/错误码 |
| 场景（链路） | 验证多接口协作与数据流转 | 登录 → 加购 → 下单 → 支付 → 退款 |

**场景用例设计要点：**

- 依赖显式声明，禁止隐式顺序依赖；
- 上游输出作为下游输入的提取与传递（token、orderId）；
- 跨系统校验：接口 + DB + MQ + 第三方（Mock）；
- 异常注入：链路中间环节失败时的补偿与最终一致性。

## 十一、常见接口类型用例模板

### 11.1 登录

正常登录（3 种账号形态）、密码错误、账号不存在、账号锁定、验证码错误/过期/复用、记住我、多端登录互踢、退出后 Token 失效、Token 过期、弱口令拒绝、并发登录、SQL 注入、错误提示不泄露账号是否存在。

### 11.2 注册

手机号格式/已注册/未注册、验证码正确/错误/过期/复用/频率限制、密码强度（长度/复杂度/弱口令/一致性）、协议勾选、邀请码、重复提交、并发注册同手机号、异常中断后重试。

### 11.3 列表查询

分页参数边界（page=0/-1/超大）、pageSize 上限、排序字段合法性与注入、筛选条件组合、空结果、总数为 0、深分页性能、结果权限过滤（只能看自己的数据）、敏感字段不返回。

### 11.4 下单

商品存在/下架/售罄、库存边界（0/1/超大）、限购（每人/每单）、价格校验（篡改金额）、优惠券叠加/互斥/过期、地址必填、运费计算、重复提交（幂等）、并发下单超卖、下单后库存与订单状态一致性。

### 11.5 支付

支付方式、金额精度、支付成功/失败/超时/取消、回调丢失重试、重复回调幂等、金额篡改、越权支付他人订单、退款全流程（部分/全额）、对账、渠道维护降级、并发支付、风控拦截。

### 11.6 文件上传/导出

格式白名单、大小边界、空文件、双扩展名、恶意文件、断点续传、秒传、并发上传、权限、存储路径安全、导出鉴权、大数据量导出异步化、下载文件内容校验。

## 十二、用例编写规范与模板

| 字段 | 要求 |
| --- | --- |
| 用例 ID | 模块-接口-序号，唯一可追溯 |
| 标题 | 一句话描述场景（条件+预期） |
| 优先级 | P0 主流程/资损；P1 核心异常；P2 边界；P3 体验 |
| 前置条件 | 数据、鉴权、依赖服务状态 |
| 请求 | 方法、路径、头、参数（可参数化） |
| 预期 | 状态码、业务码、字段断言、落库断言、副作用断言 |
| 清理 | 数据回收动作，保证可重复执行 |
| 自动化 | 是否已自动化、脚本位置 |

**用例示例：**

```
ID: PAY-REFUND-003
标题: 已退款订单再次退款返回业务错误且不重复出款
优先级: P1
前置: 订单 ORDER-1001 已全额退款，退款流水 REF-001 存在
请求: POST /api/refund {"orderId":"ORDER-1001","amount":99.00}
预期:
  - HTTP 200, code=40009 "订单已退款"
  - 退款流水数量仍为 1
  - 账户余额不变
清理: 无（只读校验）
```

## 十四、常见遗漏点 Top 15

1. 只测 200，不测业务错误码；
2. 忘记测"空数组"与"null"的区别；
3. 忽略幂等与重复提交；
4. 不校验落库，只看接口返回；
5. 忽略权限矩阵，只测管理员；
6. 忘记测超时与降级；
7. 分页只测第一页；
8. 金额只测整数；
9. 文件上传只测正常文件；
10. 忽略请求头校验；
11. 不测并发（超卖/重复扣款）；
12. 忽略历史数据兼容；
13. 不清理测试数据导致不可重复；
14. 忽略异常场景下的日志与监控；
15. 不测接口的性能边界（深分页、大响应）。

## 十五、实战演练

### 15.1 列表接口（带 type/pagesize/pageno）

> 题目：type=1 图文、2 视频、3 纯文本，pagesize、pageno 分页。

**设计要点：**

- type 枚举：1/2/3 各自返回结构差异（视频带时长、图文带封面）；
- type 非法值（0/4/字符串/空）；
- pagesize：1/上限/上限+1/0/-1/超大；
- pageno：1/末页/超出范围（返回空还是报错）/0/负数；
- 组合：type=2 且 pagesize 最大；
- 排序与去重：相邻页无重复、时间序正确；
- 内容安全：下架/审核中内容不返回；
- 性能：深分页（pageno 很大）与首屏。

### 15.2 注册成功后登录失败怎么排查？

```
1. 接口层：注册返回是否真的成功？密码是否入库（加密后比对）？
2. 链路层：注册写主库、登录读从库 → 主从延迟？
3. 状态层：账号是否被风控/未激活/待审核？
4. 密码层：加密算法/加盐是否一致？前后空格是否 trim 不一致？
5. 会话层：注册后 Token 是否有效？是否有登录态缓存未刷新？
6. 定位手段：分别调注册与登录接口看返回；查库比对密码哈希；看服务日志与 Trace。
```

## 十六、总结

> 接口用例设计 = **契约完整性 × 维度系统性 × 数据闭环 × 自动化可行性**。
> 记忆口诀：**功能参数权，数据性能安**（功能、参数、权限、数据、性能、安全）。
