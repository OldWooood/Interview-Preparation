# 🔐 安全测试用例设计完全指南

> 从"点几个注入 payload"升级为体系化安全测试：
> 认证 → 会话 → 访问控制 → 注入 → 文件 → 数据 → 业务 → API → 移动端，附工具链与报告方法。
> ⚠️ 前提：所有测试必须在**获得授权**的环境进行，禁止对未授权系统测试。

---

## 一、安全测试基础

### 1.1 威胁模型入门

| 要素 | 说明 |
| --- | --- |
| 资产 | 用户数据、资金、配置、源码 |
| 攻击面 | 登录口、API、上传、第三方回调、管理后台、移动端 |
| 攻击者 | 外部黑客、内部越权用户、薅羊毛团伙、爬虫 |
| 攻击链 | 信息收集 → 漏洞利用 → 提权 → 横向移动 → 数据窃取 |

### 1.2 测试范围

- Web 前端与接口、移动端 App、小程序；
- 认证授权、业务逻辑、数据存储与传输；
- 依赖与供应链（开源组件、第三方 SDK）；
- 合规：个人信息保护法、等保、GDPR（按业务）。

### 1.3 常见安全测试类型

| 类型 | 说明 |
| --- | --- |
| SAST | 静态代码扫描（SonarQube、CodeQL） |
| DAST | 动态扫描（Burp、ZAP、nuclei） |
| IAST | 运行时插桩扫描 |
| SCA | 依赖组件漏洞（Dependency-Check、SCA 平台） |
| 手工渗透 | 逻辑漏洞与组合攻击（自动化替代不了） |
| 红蓝对抗 | 真实攻击模拟 |

## 三、身份认证测试

| 测试点 | 用例 | 预期 |
| --- | --- | --- |
| 弱口令 | 注册/改密输入 123456、password、admin、手机号 | 提示强度不足并拒绝 |
| 口令策略 | 长度/复杂度/历史密码/定期修改 | 符合策略要求 |
| 暴力破解 | 连续错误 5/10 次 | 锁定/验证码/延迟递增 |
| 账号枚举 | 错误提示区分"账号不存在/密码错误" | 不区分或加验证码 |
| 验证码 | 空、错误、复用、过期、万能码、OCR 绕过、接口直接绕过 | 一次性、有有效期、服务端校验 |
| 找回密码 | 改包跳过验证、重置链接可猜测、Token 复用 | 强校验、一次性、限时 |
| 短信轰炸 | 高频调用发送接口 | IP/手机号/设备多维限流 |
| 多端登录 | 多设备同时在线、互踢策略 | 符合设计且旧会话失效 |
| SSO/OAuth | state 校验、回调地址白名单、授权码复用 | 防 CSRF 与开放重定向 |
| 第三方登录 | 伪造 code/token、绑定他人账号 | 服务端强校验 |

## 四、会话与 Token 管理

| 测试点 | 用例 | 预期 |
| --- | --- | --- |
| Session 固定 | 登录前后 SessionID 是否变化 | 登录后重新生成 |
| Session 超时 | 长时间无操作 | 自动失效 |
| 注销 | 退出后旧会话/Token | 立即失效（服务端注销） |
| 并发会话 | 同一账号多处登录 | 按策略限制 |
| Cookie 属性 | HttpOnly/Secure/SameSite | 敏感 Cookie 均设置 |
| JWT-过期 | 使用过期 Token | 拒绝 |
| JWT-签名 | 篡改 payload、弱密钥爆破 | 签名验证失败 |
| JWT-alg | 改成 none/对称算法混淆 | 拒绝 |
| JWT-敏感信息 | payload 是否含手机号/权限明文 | 不含敏感信息 |
| JWT-注销 | 退出后 Token 是否仍可用 | 黑名单/短过期机制 |

## 五、访问控制（重点）

### 5.1 权限测试矩阵

| 接口 \ 角色 | 游客 | 普通用户 | VIP | 运营 | 管理员 |
| --- | --- | --- | --- | --- | --- |
| 查询商品 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 下单 | ❌ | ✅ | ✅ | ❌ | ❌ |
| 改价 | ❌ | ❌ | ❌ | ✅限额 | ✅ |
| 导出用户数据 | ❌ | ❌ | ❌ | 审批后 | ✅ |
| 删除数据 | ❌ | ❌ | ❌ | ❌ | ✅二次确认 |

### 5.2 用例设计

- **水平越权（IDOR）**：修改 userId/orderId/fileId 访问他人资源；遍历 ID；用旧订单 ID 访问新用户订单；
- **垂直越权**：普通用户直接调管理接口；被禁用账号仍可调用；前端隐藏但接口未校验；
- **未授权访问**：无 Token 调用；伪造 Token 结构（改 base64 payload）；
- **批量操作越权**：批量接口中混入他人 ID；
- **导出/下载越权**：导出全量数据；文件 URL 可猜测（无签名、无过期）。

**技巧：** 权限校验要覆盖"接口层"，不能只看前端菜单隐藏；用低权限账号 + 抓包改包逐接口验证。

## 六、注入类测试

### 6.1 SQL 注入

```
' OR 1=1 --
' OR '1'='1
1; WAITFOR DELAY '0:0:5'--      (时间盲注)
1' AND SLEEP(5)-- 
' UNION SELECT username,password FROM users--
```

**测试点：** 数值型/字符型参数、排序字段（`order by 1,2--`）、搜索框、报表导出、JSON 嵌套参数、X-Forwarded-For 等头部。

**判断依据：** 报错信息、布尔差异、时间延迟、UNION 回显、工具（sqlmap）验证。

### 6.2 NoSQL 注入

```json
{"username": {"$gt": ""}, "password": {"$gt": ""}}
{"username": {"$ne": null}}
```

### 6.3 命令注入

```
; ls
| cat /etc/passwd
$(whoami)
`id`
```

常见入口：ping/traceroute 工具、文件转换、图片处理、导出功能。

### 6.4 模板注入（SSTI）

```
{{7*7}}  →  若回显 49 存在模板注入
${7*7}
```

### 6.5 反序列化与 XXE

- 反序列化：构造恶意序列化数据（Java/PHP/Python），验证是否执行；
- XXE：上传/解析 XML 时引用外部实体读取文件（`<!ENTITY xxe SYSTEM "file:///etc/passwd">`）。

## 七、XSS / CSRF / SSRF / 重定向 / 点击劫持

### 7.1 XSS

| 类型 | 场景 | Payload 示例 |
| --- | --- | --- |
| 反射型 | 搜索、错误提示回显 | `<script>alert(1)</script>` |
| 存储型 | 评论、昵称、地址、富文本 | `<img src=x onerror=alert(1)>` |
| DOM 型 | 前端 location/hash 渲染 | `#<img src=x onerror=...>` |

**绕过技巧：** 大小写、双写、编码（HTML/URL/Unicode）、SVG、事件属性、`javascript:` 伪协议。
**验证点：** 输出编码、富文本白名单过滤、CSP 策略、Cookie HttpOnly。

### 7.2 CSRF

- 敏感操作是否有 CSRF Token；
- Token 是否绑定会话、一次性；
- SameSite 属性；
- 构造跨站表单验证是否被拦截。

### 7.3 SSRF

- URL 类参数（图片加载、Webhook、导入）指向：`http://127.0.0.1`、内网 IP、云元数据 `169.254.169.254`；
- DNS Rebinding、302 跳转绕过白名单；
- 验证：内网探测是否成功、是否限制协议（file:///gopher://）。

### 7.4 开放重定向

`?redirect=https://evil.com` → 是否直接跳转；测试白名单校验与相对路径处理。

### 7.5 点击劫持

页面是否可被 iframe 嵌套（检查 `X-Frame-Options`/CSP frame-ancestors）。

## 八、文件与数据安全

### 8.1 文件上传

| 用例 | 预期 |
| --- | --- |
| 改扩展名（.jpg → .php） | 服务端按内容校验 |
| 双扩展名（shell.php.jpg） | 拒绝 |
| Content-Type 伪造 | 以真实文件头为准 |
| 图片马（GIF89a + PHP） | 二次渲染/隔离存储 |
| 超大文件 / 压缩炸弹 | 限制大小与解压比 |
| 路径穿越文件名（../../） | 重命名/白名单 |
| SVG 上传 | 过滤脚本（存储 XSS） |
| 存储位置 | 不可执行目录、独立域名 |

### 8.2 数据传输

- 全站 HTTPS，HSTS；
- 登录/支付通道是否强加密；
- 证书校验（App 是否忽略证书错误）；
- 明文协议（HTTP/FTP）残留。

### 8.3 数据存储

- 密码加盐哈希（bcrypt/argon2），非 MD5/明文；
- 身份证/银行卡加密存储；
- 日志与导出文件脱敏；
- 备份文件权限与加密。

### 8.4 敏感信息泄露

- 错误页堆栈/SQL/路径；
- 响应中多余字段（password、idCard、token）；
- 源码泄露（.git、.svn、map 文件）；
- 调试接口/Actuator/Druid 未授权。

## 九、业务安全（区别与普通功能测试的核心）

| 场景 | 攻击方式 | 测试用例 |
| --- | --- | --- |
| 金额篡改 | 改 price/amount/运费字段 | 服务端以商品库价格重算 |
| 数量为负 | count=-1 导致退款/加钱 | 校验范围 |
| 优惠券滥用 | 叠加、重复用、过期用、改券 ID | 规则与并发校验 |
| 重复支付 | 并发/重放支付请求 | 幂等、只扣一次 |
| 退款套现 | 支付后立即退款、部分退款循环 | 风控与对账 |
| 刷单/薅羊毛 | 批量注册、脚本抢购、模拟器 | 设备指纹、风控、限购 |
| 库存超卖 | 并发下单 | 锁/队列/超卖校验 |
| 越权改单 | 改地址/手机号 | 归属校验 |
| 验证码接码 | 虚拟号段批量注册 | 号段风控、行为验证 |
| 抽奖/秒杀 | 脚本高频、篡改中奖率 | 限流、签名、服务端随机 |
| 数据爬取 | 遍历接口、无频率限制 | 限流、验证码、数据水印 |

**设计思路：** 找"利益点"（钱、券、货、数据）→ 梳理规则 → 找规则漏洞（并发、时序、边界、多入口）→ 构造最小成本攻击链。

## 十、移动端安全专项

| 测试点 | 方法 | 预期 |
| --- | --- | --- |
| 本地存储 | 检查 SharedPreferences/SQLite/Keychain | 不存敏感明文 |
| 组件暴露 | drozer/adb 调起未导出组件 | 敏感 Activity/Receiver 不导出或校验 |
| 日志泄露 | logcat 过滤关键字 | 无敏感日志 |
| 抓包对抗 | 代理抓包、证书校验 | 关键接口证书绑定（按需） |
| 调试检测 | root/越狱/调试器附加 | 风险环境提示或限制 |
| 加固与混淆 | 反编译查看 | 核心逻辑混淆、无硬编码密钥 |
| 截屏/录屏 | 支付页截屏 | 按需防截屏 |
| 界面劫持 | 覆盖层攻击 | 防覆盖校验 |
| 升级安全 | 伪造更新包 | 签名校验、HTTPS 下载 |

## 十一、日志与审计

- 关键操作（登录、支付、改密、删数据、导出、权限变更）必须有审计记录；
- 日志含：谁、何时、从哪、做了什么、结果；
- 敏感信息（密码、Token、证件号）禁止入日志；
- 审计日志不可被普通用户篡改；
- 告警有效性：异常登录、批量操作是否触发告警。

## 十二、异常处理与配置安全

| 检查项 | 预期 |
| --- | --- |
| 错误页面 | 统一友好提示，无堆栈/SQL/路径 |
| 目录遍历 | 无目录列表、无源码/备份可下载 |
| 默认口令 | 管理后台/中间件无默认弱口令 |
| 调试开关 | 生产关闭 debug/actuator/swagger 敏感暴露 |
| CORS | 不发 `Access-Control-Allow-Origin: *` + 凭证 |
| HTTP 方法 | 关闭不必要的 PUT/DELETE/TRACE |
| 请求头 | 安全头齐全（CSP、X-Frame-Options、HSTS） |
| 第三方依赖 | 无高危 CVE 组件 |

## 十三、工具链与流程

### 13.1 工具

| 工具 | 用途 |
| --- | --- |
| Burp Suite | 抓包改包、扫描、重放、越权测试 |
| OWASP ZAP | 开源 DAST 扫描 |
| sqlmap | SQL 注入验证 |
| nuclei | 模板化漏洞扫描（CVE/配置） |
| nmap | 端口与资产探测 |
| drozer / MobSF | 移动端安全 |
| Dependency-Check / SCA | 组件漏洞 |
| SonarQube / CodeQL | 代码静态扫描 |

### 13.2 流程

```
资产与接口梳理 → 自动化扫描（SAST+DAST+SCA）
→ 手工验证与逻辑测试 → 漏洞定级 → 修复建议
→ 开发修复 → 复测 → 回归与上线
```

### 13.3 漏洞定级（参考 CVSS 思路）

| 维度 | 说明 |
| --- | --- |
| 可利用性 | 是否需要认证/交互、难度 |
| 影响范围 | 数据、资金、权限、可用性 |
| 影响程度 | 单个用户 / 全量用户 / 系统级 |
| 综合 | 高危（可直接拿数据/钱）、中危（需组合利用）、低危（信息泄露但价值低） |

**报告要素：** 漏洞描述、复现步骤、请求响应证据、影响评估、修复建议、复测结果。

## 十五、检查清单

- [ ] 认证：弱口令、爆破、枚举、验证码、找回密码、多端
- [ ] 会话：固定、超时、注销、JWT、Cookie 属性
- [ ] 权限：水平/垂直/未授权/批量/导出（含接口层）
- [ ] 注入：SQL/NoSQL/命令/模板/XXE/反序列化
- [ ] 前端：XSS/CSRF/点击劫持/开放重定向
- [ ] SSRF：内网、元数据、协议限制
- [ ] 文件：上传绕过、路径穿越、下载鉴权
- [ ] 数据：传输、存储、日志、错误泄露
- [ ] 业务：金额、幂等、优惠、风控、超卖
- [ ] 配置：默认口令、调试接口、CORS、安全头
- [ ] 审计：日志内容与告警有效性
- [ ] 供应链：组件 CVE 与 SDK 版本

---

## 十六、总结

> 安全测试 = **认证可信 × 权限最小 × 输入不可信 × 数据不外泄 × 业务无套利**。
> 面试加分点：不只报 payload，而是讲清"攻击链 + 影响面 + 修复方案 + 如何回归验证"。
